# Формат каталога — нормативное описание

🇷🇺 Русский · 🇬🇧 [English](SPECIFICATION.md)

> **Нормативный источник — английский [`SPECIFICATION.md`](SPECIFICATION.md).** Перевод сделан

**Версия 1.** Документ описывает CSV-формат обмена, используемый этим репозиторием.

Это **выдержка для удобства**. Нормативный источник всего, что касается протокола, — ID
профилей, требование публичной идентичности, точка `.well-known/odp.json`, аффилиация и то, что
каталогу разрешено утверждать, — это
[`SPEC.md`](https://github.com/object-digital-passport/specifications/blob/main/SPEC.md), §3 и §4.
При расхождении этого файла со `SPEC.md` побеждает `SPEC.md`.

Слова **ОБЯЗАН** (MUST), **НЕ ДОЛЖЕН** (MUST NOT), **СЛЕДУЕТ** (SHOULD), **МОЖЕТ** (MAY)
употребляются в смысле RFC 2119.

---

## 1. Что каталогу разрешено утверждать

Каталог — оффчейн-удобство. Он **НЕ ДОЛЖЕН** подаваться как истина протокола.

Кто угодно **МОЖЕТ** опубликовать собственный каталог в этом формате, со своими правилами приёма
и своими данными: этот репозиторий — пример формата, а не реестр, от которого зависят остальные.
Правила ниже ограничивают, что любой такой каталог вправе **утверждать**, а не то, кто вправе его
вести.

Любой опубликованный каталог **ОБЯЗАН** прямо сообщать: строки отобраны его оператором,
отсутствие записи ничего не означает, наличие записи ничего не гарантирует.

Каждый перечисленный ID профиля **ОБЯЗАН** сопровождаться хотя бы одним HTTPS-адресом на
официальном сайте самой организации — страницей, где этот же ID видимо опубликован, — чтобы
читатель мог подтвердить связку, не полагаясь на оператора каталога. Каталог, перечисляющий ID
без таких ссылок, **НЕ ДОЛЖЕН** подаваться как авторитетный.

`displayName` **не авторитетно** и ничем не подтверждается. Авторитетны ID профиля, реестр,
которому он принадлежит, и `evidenceUrl`.

## 2. Идентичность файла

Имя CSV-файла **ОБЯЗАНО** иметь вид `odp-directory-v<MAJOR>.<MINOR>.csv` и называть генерацию
реестра, которой принадлежат строки. Один файл описывает ровно одно развёртывание реестра; ID
сети и адрес контракта для него **ОБЯЗАНЫ** быть записаны в `config.json` и перенесены в
собранный `directory.json`.

ID профиля бессмыслен без своего реестра: тот же кошелёк получает **другой** ID в другом
развёртывании (`SPEC.md`, раздел «0.x deployments»). Каталог, не указывающий реестр, становится
неоднозначным в день выхода новой генерации.

## 3. Кодировка и раскладка

- UTF-8, **без BOM**. Переводы строк **LF**. Файл **ОБЯЗАН** заканчиваться переводом строки.
- RFC 4180. Поля берутся в кавычки только там, где это требуется (`,`, `"`, перевод строки).
  `""` — экранированная кавычка.
- Одна строка заголовка: ровно двенадцать имён колонок ниже, в этом порядке.
- Строки **ОБЯЗАНЫ** быть отсортированы по `profileId` по возрастанию, в байтовом порядке.
- `profileId` **ОБЯЗАН** быть уникален в пределах файла.
- Пустое значение — пустое поле, а не `null`, `-` или `n/a`.
- Даты по ISO 8601: `YYYY-MM-DD` для дней, `YYYY-MM-DDThh:mm:ssZ` (UTC) для моментов времени.

## 4. Колонки

| # | Колонка | Тип | Обяз. | Правило |
|:--|:--|:--|:--|:--|
| 1 | `profileId` | строка | да | `^[CBPM]-\d{3}-\d{3}-\d{3}-\d{3}$` |
| 2 | `profileType` | перечисление | да | `C` `B` `P` `M`; **ОБЯЗАН** совпадать с `profileId[0]` |
| 3 | `displayName` | строка | нет | Неавторитетный ярлык |
| 4 | `evidenceKind` | перечисление | да | `website` `social` |
| 5 | `evidenceUrl` | URL | да | HTTPS |
| 6 | `evidenceHost` | хост | да | **ОБЯЗАН** совпадать с хостом `evidenceUrl` |
| 7 | `checkMethod` | перечисление | да | `auto` `manual` |
| 8 | `status` | перечисление | да | §5 |
| 9 | `lastCheckedAt` | момент | условно | Ставит проверяльщик; пусто при `checkMethod=manual` |
| 10 | `lastVerifiedAt` | дата | условно | **ОБЯЗАНА** быть при `checkMethod=manual` |
| 11 | `archiveUrl` | URL | условно | **ОБЯЗАН** быть при `checkMethod=manual` |
| 12 | `addedAt` | дата | да | |

Дополнительные ограничения:

- `evidenceKind=social` **НЕ ДОЛЖЕН** иметь `checkMethod=auto`. Ни одна платформа не отдаёт
  `/.well-known/odp.json` за своих пользователей, поэтому такая строка заявляла бы машинную
  проверку, которой не было.
- `checkMethod=auto` **ОБЯЗАН** иметь `lastCheckedAt`, кроме случая `status=withdrawn`.
- `status=unverifiable` **ОБЯЗАН** иметь `checkMethod=manual`.

Каталог **НЕ ДОЛЖЕН** содержать колонок аффилиации (родитель/ребёнок). Это отношение живёт
on-chain (`getAffiliatedParent`), и копия в правимом руками файле с ним разойдётся. Адреса
кошельков так же читаются из реестра (`getCreator`), а не хранятся здесь.

## 5. Семантика статусов

| Статус | Значение | Приложение **ОБЯЗАНО** |
|:--|:--|:--|
| `active` | Доказательство проверено и на месте | Может показывать идентичность организации |
| `unreachable` | Сетевая ошибка, 5xx или 404 | Не показывать **никакой** идентичности — и **никакого** предупреждения |
| `unverifiable` | Машинно нечитаемо в принципе (соцсеть, клиентский рендер) | Показывать с датой последней ручной проверки |
| `removed` | Точка отдаётся, но ID в ней больше нет | Показывать заметное предупреждение на записи |
| `withdrawn` | Снят по запросу или оператором | Не показывать ничего; строка — история |

`unreachable` и `removed` **НЕ ДОЛЖНЫ** схлопываться в одно состояние. Сайт, который не
открылся, — это отсутствие данных; ID, намеренно удалённый со страницы, которая по-прежнему
отвечает, — поступок. Подача первого как второго обвиняет честные организации из-за обычного
простоя.

Предупреждение **НЕ ДОЛЖНО** выставляться доказательству, которое никогда не было машиночитаемым.
Отсутствие находки — не находка.

## 6. Перепроверка

- Машинная перепроверка читает `https://<evidenceHost>/.well-known/odp.json` (`SPEC.md` §3) —
  никогда человеческую страницу. Профиль считается перечисленным, только если `profileId` записи
  совпал **и** её действующие `chainId` и `registry` совпали с реестром файла.
- Ответ 200 не в JSON (одностраничное приложение, отвечающее на любой путь) — это
  **UNREADABLE**, а не `removed`.
- `unreachable` **СЛЕДУЕТ** выставлять только после нескольких неудач подряд — трёх в
  конфигурации этого репозитория, — чтобы короткий простой не менял то, что видят пользователи.
- `removed` **ОБЯЗАН** быть достижим только для профиля, который проверяльщик ранее находил. Этот
  факт проверяльщик **ОБЯЗАН** сохранять между запусками.
- Ручные строки **СЛЕДУЕТ** периодически перепроверять человеку — здесь раз в 183 дня — и
  показывать их протухание.

## 7. Собранный JSON

`directory.json` генерируется из CSV и **ОБЯЗАН** нести версию формата, линию спеки, ID сети,
адрес реестра, имя исходного файла, момент сборки, число строк, отказ от кураторских претензий и
сами записи. Приложениям **СЛЕДУЕТ** читать JSON; CSV — правимый источник истины.
